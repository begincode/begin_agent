# 第十二步 角色目录、权限矩阵与成员联动

状态：已完成。对应角色权限原型，承接第十一步的独立账号工作区。

## 实现

- `GET /api/v1/roles` 增加名称/编码搜索、状态筛选、稳定分页。内置角色与自定义角色统一占用分页位置，默认 50、最大 100，保留 `roles`、`permissions` 响应键。
- 当前页逐角色展示权限矩阵、成员总数和启用账号成员数。计数要求 `members.manage`，无权限返回 `null` 并显示“—”；同一条聚合查询只统计当前页角色及当前租户。
- 成员总数包括停用记录，启用账号成员数同时检查账号和成员状态；该数字不等同于有效登录人数，角色、平台身份与租户状态仍影响访问。
- 角色编辑按任务、Agent、运行、资源、成员、角色、租户、审计分组。内置角色只读；自定义角色仅在其现有权限不超出操作者权限时可修改，服务端同步检查，不能通过覆写低权限请求间接撤销高权限角色。
- 保存本人角色后重新获取身份和工作区数据，失去角色管理权限即退出该页、移除导航。禁止停用当前使用的角色，防止失去当前租户访问入口。
- 角色停用或权限变化在后续鉴权中生效，成员详情显示对应的实际权限和访问受阻原因；不改写既有 Agent 版本与执行历史。
- 主要代码：`app/services/roles.py`、`app/api/workspace.py`、`RolesWorkspace.vue`、`AdminView.vue`、`platform.css`。不增加数据库结构。
