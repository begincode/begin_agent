# 第十八步：Agent 多人编辑并发保护

日期：2026-11-06。用户确认本步范围后，按[需求规格](../specs/feature-agent-concurrent-editing.md)实现。验收映射见[验证报告](../specs/feature-agent-concurrent-editing-verification.md)。

## 解决的问题

草稿接口原来已经比较 revision，但编辑器先 PATCH Agent 名称、类型、状态，再 PUT 草稿，最后发布。第二步冲突时，第一步的元数据已经提交。协作配置还采用最后保存覆盖，发布时也无法知道页面打开后关系或子版本发生了变化。

本步把已有 Agent 的元数据、草稿和可选发布合并到一次事务；用服务器生成的强 ETag 比较编辑者看到的状态。版本、任务、Run、产物等历史记录继续保持原来的不可变约束。

## 接口和事务

| 读取入口 | 写入入口 | 前置条件 |
|---|---|---|
| GET `/agents/{code}/configuration` | PUT 同路径，包含 agent、config、publish | 响应 ETag 或 body.etag |
| GET `/agents/{code}/configuration` | POST `/agents/{code}/versions`、`/rollback` | 配置快照 ETag |
| GET `/agents/{code}/relations` | POST 关系、PATCH/DELETE 单条关系 | 关系集合响应 ETag |
| GET `/agents/{code}` | PATCH Agent 元数据 | 响应 ETag 或 body.edit_etag |
| POST `/agents` | 随后的首次配置保存 | 创建响应 configuration_etag |

上表路径均有 `/api/v1` 前缀。条件写入携带 `If-Match`；合法请求缺少条件返回 **428**，条件过期返回 **412**，不提供强制覆盖或自动重试。既有 PUT draft 保留 revision 比较及 409 行为，它只修改草稿，不承担元数据与发布的组合保存。旧接口调用方需要按此协议升级，不能继续不带条件更新元数据、关系或发布。

配置快照包含 Agent 元数据、草稿及其 revision、协作列表和当前子版本。关系集合使用自己的令牌，不因无关的父 Agent 草稿变化阻止单独编辑关系；子 Agent 名称、状态或当前版本变化会使相应令牌改变。令牌根据配置内容生成，是内容比较标识，不是鉴权凭据，也不是单调递增的全系统版本号。相同可见状态可以产生相同令牌。

需要关系图锁的路径先取得租户图事务锁，再取得 Agent 行锁；单关系写入随后锁关系。纯元数据和旧草稿写入只取行锁，不反向获取图锁。条件在锁内核对，图变更仍检查自调用、重复和循环；超过关系读取上限明确拒绝，不对截断列表生成可写令牌。

原有发布服务增加不独立提交的调用方式，组合保存直到全部校验与版本构建通过才统一提交。模型停用、参数错误、授权撤销或发布冲突均不会留下部分名称、草稿或版本。条件校验只读取必要配置，不为校验拉取版本全集；协作面板沿用关系列表和响应 ETag。版本列表之外的当前历史版本也能单独回读，避免回滚到较老版本时找不到配置来源。

页面读取和写入仍逐次验证用户、租户及权限。组合保存要求 agents.manage，发布额外要求 agents.publish；只有发布权限的账号仍可使用单独发布入口，不能绕过配置写权限修改元数据。停用租户只读，跨租户编码不能用于本租户更新。没有数据库结构变化，迁移仍为 `20261029_06`。

## 冲突与新建恢复

冲突后保留本地名称、提示词及关系编辑字段，显示独立冲突面板，并禁用重复保存、发布及关系写操作。用户先点“重新加载配置”，再确认“放弃本地修改并加载”；选择保留不会读取或替换输入。重新加载失败仍保留本地内容；成功后才替换表单和令牌。读取使用 AbortSignal 和请求序号，离开页面释放请求。

新建向导拿到创建编码后保留该编码，使用创建响应提供的初始条件，避免在保存前重新获取新条件后盲目覆盖并发修改。已创建但后续保存冲突时，确认重新加载会读取该 Agent；服务器没有草稿和版本时还原默认配置，不能把被确认放弃的本地提示词继续留在表单。恢复保存不会再次创建 Agent。复制历史配置时也复制本地数据对象，避免表单修改影响页面中的历史快照对象。

这个恢复保证以已经拿到创建编码为前提。首次创建请求若已经提交但响应丢失，客户端仍无法判断是否创建成功；创建接口幂等键与跨页面草稿恢复不属于本步。

- 两个独立 Chromium 会话分别登录平台管理员与租户编辑者。A 保存名称/提示词后，B 的过期保存返回 412；B 的本地长名称和长提示词保留，服务器保持 A 的成对字段。确认前不替换，网络故障下重新加载失败仍保留输入，恢复后可发布。
- 协作编辑中 A 改为并行/31 秒，B 的过期 7 秒更新被拒绝；再以 44 秒变更制造过期删除，确认关系仍在。重新加载后删除成功，再创建新关系，旧快照不改写。
