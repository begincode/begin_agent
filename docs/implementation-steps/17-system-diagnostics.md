日期：2026-11-06。用户确认本步范围后，按[需求规格](../specs/feature-system-diagnostics.md)实现。独立账号继续使用，不恢复 SSO；未登记远程 PMS。

## 交付内容

入口为“系统状态” `#/integrations`，沿用 `GET /api/v1/integration-status`，补齐采样时间、数据库连接与迁移、本机 Worker 心跳和当前租户队列。页面支持手动刷新、初始加载、失败重试；刷新失败保留上次样本并明确标记“当前状态尚未确认”，不把旧的绿色状态当作新检查结果。读取过程中按钮禁用，离开页面、身份或租户变化会中止请求并丢弃旧响应。

数据库检查使用三秒超时及独立保存点，检查目标迁移 `20261029_06`。迁移不匹配与检查失败分别展示，失败只返回脱敏状态，不回显 DSN、SQL 或底层异常。保存点保证一次检查失败不必破坏后续诊断；身份验证本身依赖数据库，认证阶段已失败时仍按原接口返回，不能承诺此页能在全库断连时继续工作。

Worker 心跳文件增加 hostname，兼容旧文件中 worker_id 的主机部分。只把本机、有效窗口内且 PID 可观察的记录计为就绪；过期或退出、损坏、其他主机和无法观察分别统计。扫描最多 256 条、单文件最多 16KiB，拒绝符号链接、非法 PID、非有限数字和未来时间，超过扫描上限显示统计不完整。写入仍采用临时文件加原子替换，命令 `python -m app.workers.readiness` 沿用同一规则。

本机 PID 检查只适用于同主机且可见相同进程命名空间和数据目录的部署。API 与 Worker 分布在不同主机或独立容器时，其他主机记录不会冒充本机就绪；Worker 自身的 readiness 命令应在其运行环境执行。本步没有增加跨主机心跳注册中心，也不以 PID 检查证明进程身份。

## 队列口径与权限

状态接口先验证当前租户存在及 `tenant.manage`。队列额外要求 `tasks.read`，没有权限时返回 `queue.status=forbidden`，不查询任务指标或返回任务样本。停用租户可只读查看；每次查询都带 tenant_code，并继续使用原 RLS。

| 指标 | 口径 |
|---|---|
| 待执行 | 当前 PENDING 任务 |
| 可领取 | PENDING 且计划时间和下次重试时间均已到达 |
| 计划或重试等待 | PENDING 但较晚的计划/重试时间尚未到达 |
| 运行中 | 当前 RUNNING 任务 |
| 租约过期 | RUNNING 且租约到期时间不晚于数据库采样时间 |
| 缺少租约 | RUNNING 但没有租约到期时间 |
| 长时间等待 | 可领取后等待至少 300 秒 |
| 最近一天失败/超时 | 当前 FAILED/TIMEOUT 且 finished_at 位于最近 24 小时内 |

最长等待从计划时间和重试时间中较晚者计算，避免正常重试退避误报积压。异常样本优先展示租约问题，再展示长等待和近期失败，最多十条；返回任务编码、标题、状态、原因和观察时间，提供详情入口，不读取提示词、结果正文或租约令牌。指标是当前状态的只读采样，不是冻结历史；有并发变化时汇总与样本可能略有差异。

本页面不领取、取消、重试或修复任务。租约过期仍由现有 Worker 规则处理；缺失租约的异常应沿任务记录排查，不能宣称一定会自动恢复。
