# 第一步：任务执行工作区

状态：已完成。依据原型 `task-detail.html` 的可折叠执行链、轮次/Run/Token 摘要以及“我的任务”列表。

## 验收标准

- 桌面任务对话右侧可展开/收起执行链；窄屏通过运行链路页签查看，不挤出底部输入框。
- 查询真实 Run、父子关系、轮次、名称、已记录步骤、最近步骤、耗时与模型 Token。没有用量时显示未知，不伪造进度百分比。
- 执行期间随任务轮询更新；切换任务或离开页面停止更新；执行链失败不阻止读取已有对话。
- 执行摘要同时需要任务读取与运行读取权限；只能读取当前租户已有任务；不返回模型密钥、完整上下文或工具输入。
- 列表支持“全部任务/我的任务”，筛选在服务端执行并重置分页。

## 本步结果

- 新增 `GET /api/v1/tasks/{task_code}/execution`，通过当前租户与 `tasks.read`/`runs.read` 读取 Run 树、步骤摘要、真实模型 Token、轮次与耗时；不返回原始消息或工具输入。
- `GET /api/v1/tasks?mine=true` 在服务端限定创建者；前端切换范围时重置分页。默认保留全部租户任务视图。
- 任务详情右侧可折叠执行链；偏好本地保存，≤1000px 自动隐藏侧栏，通过“运行链路”页签查看。对话输入区保持独立，执行记录失败单独提示。
- 页面执行期间沿用 1.8 秒轮询；离开任务停止更新；Token 未返回时显示“—/未返回”，步骤数量表示已落库步骤，没有虚构完成百分比。
- 主要代码：`app/services/execution.py`、`app/api/workspace.py`、`app/api/platform.py`、`web/src/components/ExecutionPanel.vue`、`TaskWorkspace.vue`、`WorkspacePage.vue`。

- 本步前端完整 check：31 项功能测试、6 项 UI 规则测试、类型检查与生产构建通过。ruff 通过。

- 证据：`output/playwright/implementation-step-01/geometry.json` 与 `interactions.json`。
- 原端口 API 已更新，Worker 保持运行，无数据库迁移或用户数据变更。隔离用例使用先前模拟模型生成的真实运行记录，不把用量展示当作外部模型连通验证。

## 限制与下一步

运行状态采用短轮询，并非流式逐 Token 输出；耗时为 Run 时间，步骤仅记录已完成/失败的追加日志。本步不重写 Runtime 的步骤不可变机制。下一步补齐版本对比与测试结果读取。
