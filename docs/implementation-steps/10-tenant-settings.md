# 第十步 当前租户设置

状态：已完成。对应租户设置原型，继第九步成员目录后独立实现、编译启动与验收。

## 实现

- 新增 `GET /api/v1/tenant` 与 `PATCH /api/v1/tenant`，均要求 `tenant.manage`。目标由当前鉴权租户确定，普通管理者只能改当前启用租户的名称；请求体拒绝目标编码、状态及其他额外字段。
- 当前租户概况返回不可变编码、名称、创建时间与状态。成员和管理员数量要求 `members.manage`，Agent 数量要求 `agents.read`，资源统计要求 `resources.read`；未授权的统计返回 `null`，界面显示“—”及原因，不以零代替。
- 独立租户设置工作区展示真实数据、名称编辑、只读编码与权限相关入口。改名后重新读取身份和目录，顶栏名称即时同步，刷新后保留。
- 普通管理者不能修改租户状态。平台管理员通过既有 `/tenants` 平台接口创建、启停当前租户；停用后普通账号仍可读历史，但前端禁止编辑，服务端拒绝写入。平台管理员可以恢复启用。
- 新建首个租户后同步当前租户选择，避免无租户账号创建成功但页面不加载。创建其他租户不改变当前选择，后续可从顶栏切换。
- 主要代码：`app/services/tenants.py`、`app/domain/workspace.py`、`app/api/workspace.py`、`app/services/permissions.py`、`TenantSettings.vue` 与 `AdminView.vue`。无数据库结构变更。

## 边界

本步不增加租户删除、所有权转移或跨租户批量编辑。管理员数量统计为启用账号中的启用 `TENANT_ADMIN` 成员数，平台身份与自定义角色不混入该口径；“已有发布版本”不代表 Agent 当前启用。普通管理者的租户信息读取仍要求 `tenant.manage`，其他业务页面继续使用原有权限。

所有业务写入在隔离数据库完成，实际服务保留原账号、模型配置、密钥和业务数据；未恢复 SSO，未调用真实模型供应商。
