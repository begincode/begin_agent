# 第十九步：Agent 创建幂等与结果恢复

日期：2026-11-06。用户确认范围，承接第十八步首次创建回执丢失的边界。见[需求规格](../specs/feature-agent-creation-recovery.md)、[验证报告](../specs/feature-agent-creation-recovery-verification.md)及[独立文章](articles/19-agent-creation-recovery.md)。

## 创建协议

POST `/api/v1/agents` 可携带 `Idempotency-Key`，长度 16–128，仅允许字母、数字、下划线、点和连字符。首次提交返回 201，重放返回 200，响应头 `Idempotency-Replayed` 分别为 false/true；成功重放的审计记录标记 `idempotent_replay`。未携带键的旧调用方保持原行为，不具备创建重试去重保证。

请求范围由当前租户、当前账号及键确定。服务端保存键的 SHA256、规范化基本信息的摘要和首次响应；同范围、同键、同内容返回原始结果，同键不同内容返回 409。事务级 advisory lock 串行核对相同范围，并由唯一约束兜底。Agent 与回执同事务提交，回执写入失败不保留 Agent；提交后的审计异常即使让请求返回错误，也能使用原键恢复。

GET `/api/v1/agents/creation-requests/{key}` 查询当前账号、当前租户的回执；没有则 404。404 仅表示当前未查到，不证明原请求一定失败；客户端保留原键，让用户重试。读写均要求 agents.manage，先验证权限及租户状态；停用租户可只读查询，禁止重放写入。跨租户及其他创建者不能用已知键查询结果。

回执包含初始 configuration_etag。重放不读取最新条件、不更新 Agent 或草稿；若另一编辑者已修改配置，后续组合保存仍触发第十八步的 412，而不是拿新条件覆盖对方。保存、发布与任务历史规则继续保留。

## 向导恢复

首次提交前生成 UUID，并将原始名称、类型、状态及请求标识写入按账号/租户划分的 sessionStorage。记录不包含提示词、资源配置、模型密钥或完整向导草稿。同页失败重试始终重用原始请求体与键，确认创建编码后保存当前本地编辑，包括失败后更改的名称。

刷新后显示“恢复 Agent 创建”，隐藏默认向导。查询结果或重试原创建后进入现有配置页，不自动 PUT 刷新后的默认配置。用户需要核对已保存内容，并重新填写未保存的编辑。查询 404 保留记录；确认原 Agent 后才清除对应键，清理不会误删更晚的请求。

页面切换按当前身份读取恢复记录，异步返回再次检查身份与租户，卸载中止恢复请求。存储写入失败会明确提示，并保留当前页面内存中的原键供重试。损坏、手工清除、关闭标签页或浏览器拒绝存储后离开页面，不能保证自动找回；数据库回执仍保留，可先到列表核对。恢复记录不是身份凭据。

新增 `20261106_07`，前序 `20261029_06`，仅增加 agent_creation_receipt 表、索引、复合外键、租户 FORCE RLS 与不可变更新/删除触发器。API 数据库角色需补该表 SELECT、INSERT 和 identity 序列 USAGE；Worker 不写创建回执。迁移期望版本由 app/db/schema.py 统一维护。

回执没有 TTL 和自动清理；其存在是持续去重的依据。不能按年龄直接清除，也不能将降级删表视为无损回退；删除回执会丢失原键去重能力，外键与不可变约束也限制删除关联数据。部署时先迁移，再启动新代码，运行账号和持久主密钥沿用原配置。
