# 让文件成为任务参考，而不是隐含的系统指令

任务以前只有一段文字要求。第二十一步让用户可以补充小型文本资料，并在提交时固定原始文件及解析结果。限制到三份、每份 32KiB，是为了让上传、数据库和模型上下文的成本有明确边界。

文件名与内容都不能仅凭浏览器判断。服务端重新检查编码、类型和结构，再保存原字节的哈希；同一个任务幂等键不能换另一份附件。列表只返回元数据，下载重新验证任务权限和租户，避免把文档原文塞进每次轮询。

模型看到的是明确标记的用户参考数据。这个标记不构成对所有提示注入的绝对防护，文件也不会成为执行代码；工具调用仍受原来的白名单和权限约束。已有预算限制继续决定参考材料是否能在当前任务中处理。

浏览器选择的 Markdown 含测试脚本字样，经过真实任务与合成模型处理后，下载字节和原文件一致，页面没有执行脚本。完整后端 256 项、前端 131 项及 UI 6 项通过，12 组视口记录覆盖上传和查看。用户能够核对模型用了哪份资料，也能下载原件。
