# 从文本结果到文件交付：文件产物与私有对象存储的设计与实现

Begin Agent 的任务已经可以持续对话、调用工具与子 Agent，并展示实时正文和思考过程。不过，实际交付常常还需要报告、图片或一份压缩文件。把这些文件放到任务之外，用户就得自己记住它属于哪个任务、哪个执行轮次、由谁补充。

第十四步把文件放回任务的产物页：成功任务可以追加文件，刷新后仍能找到，也能由具有读取权限的同租户成员下载。原有文本结果继续保留复制和 Markdown 下载。

## 先明确文件的来源

这次增加的是人工上传文件。用户选择一个文件，并不意味着 Agent 生成了它，也不意味着模型已经读过它。

所以文件卡片明确显示“人工上传”、上传人、时间、文件大小和 SHA-256，并绑定任务当前成功轮次的根 Run。没有运行记录权限的成员可以下载文件，但不会看到可点击的 Run 链接。文件内容不会自动加入后续模型上下文。

上传还必须满足任务已成功、租户可写、具备任务读写权限，以及上传者是任务创建者或任务管理员。这让“补充交付文件”和“修改模型历史结果”有清楚的边界。每次上传都新增产物，既不覆盖旧文件，也不改写不可变运行记录。

## 数据库记住归属，对象存储保存字节

原来的产物表已经有 JSONB 内容字段，这一步可以直接保存文件元数据和私有存储引用，无需增加表或迁移历史记录。二进制内容进入对象存储，文件名、大小、校验值和来源信息留在数据库。

对象键只使用系统生成的实体编码，例如 `tenant/{tenantCode}/task/{taskCode}/{artifactCode}`。用户文件名可以是中文，也可以很长，但它不能决定服务器目录或桶内路径。

默认后端是持久数据目录里的私有对象目录；另一个后端通过官方 Boto3 SDK 连接 S3 兼容私有桶。本地文件先写临时对象，完成校验后原子发布；S3 使用全新的对象键和条件写入。页面不接收存储端点、桶名、对象键或预签名链接。

下载仍然经过 Begin Agent。系统确认登录会话、当前租户与任务读取权限，从存储取回文件，核对大小和 SHA-256，再以附件返回。即使上传的是 HTML，也只作为文件下载，不在产物卡片里执行。

## 处理失败比保存成功更需要推敲

一次文件上传跨越对象存储和 PostgreSQL，两者没有共同事务。对象保存成功以后，数据库提交可能失败；用户也可能取消请求，或在上传过程中失去权限。

实现采用先写对象、再复验身份与任务状态、最后提交产物记录的顺序。提交前失败，就补偿删除本次未挂接的对象。上传请求带一个重试标识，相同文件重试返回已有产物；如果同一个标识用于不同内容，则返回冲突。并发请求在任务行锁内检查，避免生成两条相同记录。

这里还有一个容易忽略的细节：S3 SDK 和本地文件操作在线程中执行，取消异步请求不会自动停止线程。代码会等待存储线程收尾，再关闭临时文件并处理补偿，避免后台仍在读取一个已经关闭的文件。

如果数据库实际上已经提交，只是客户端没有收到回执，直接删对象会破坏成功结果。因此，提交状态不明时先查数据库；数据库也不可用时保留对象并记录产物编码，交给后续核对。进程被强制终止仍可能留下孤儿对象，运行文档明确说明了这一点，没有把补偿机制写成跨系统原子事务。

## 让上传和下载的状态可信

页面默认使用服务器给出的文件上限，正式默认值为 20 MiB。空文件和超限文件会明确提示，上传期间禁用重复操作，失败后保留文件和原重试标识。上传成功与列表刷新失败分别反馈，避免让用户误以为需要再传一份。

产物目录按每页 20 条读取，继续加载后追加记录。文件卡片展示校验值，文本卡片保持原来的复制与下载操作。离开页面会中止页面请求并释放 Blob URL。

浏览器验收发现了一个真实布局问题：长连续英文文件名会撑宽卡片。修复时没有直接截掉名称，而是限制标题的宽度，并允许在连续字符间换行。用户仍能读到完整的规范化名称，手机页面也不会被撑开。

## 用实际文件检查交付链路

本步最新完整后端检查有 203 项通过、没有跳过；前端有 81 项功能测试、6 项 UI 规则，类型检查、生产构建和 Ruff 均通过。新增测试覆盖文件完整性、权限、失败补偿、并发幂等、取消和 S3 SDK 行为。

真实浏览器上传了一份 1 MiB 的二进制文件，下载后逐字节比较，并检查 SHA-256 一致。刷新页面后文件仍然可用。另用只有任务读取权限、没有运行记录权限的账号验证了分页和下载；跨租户下载返回 404。浏览器还注入了一次临时上传失败，确认文件和重试标识保留，恢复后真实保存成功。

选择文件、保存文件和只读文件三种状态分别覆盖六种规定视口，共保留十八组截图与几何数据。长文件名修复后重新编译启动并复验，检查页面和卡片溢出、统一控件尺寸、按钮对齐、Logo 居中与键盘焦点。

S3 验证使用官方 SDK 与本机隔离 HTTP 服务完成协议往返，没有调用远程云桶。模型任务也使用隔离合成模型，所有业务写入都在独立验收数据库。真实云桶联调、大文件并发、断点续传和自动孤儿对象回收仍需后续建设。

文件交付现在有了明确的任务归属、访问权限和完整性证据。下一步接入真实业务工具时，可以沿用这层存储与鉴权边界，再定义工具生成文件的来源记录和交付协议。
