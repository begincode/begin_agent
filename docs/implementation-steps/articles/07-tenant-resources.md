# Begin Agent 建设实践之七 租户资源概况与授权的设计与实现

一项资源已经建立，并不意味着 Agent 当前可以使用它。资源可能被停用，租户可能撤销了授权，MCP 连接也可能尚未发现任何工具。管理者需要看清这些状态，配置 Agent 的人则需要获得一致的选择范围。

Begin Agent 第七阶段补齐租户资源概况，把模型、工具、MCP 和 Skill 的数量、状态和授权操作放到同一页面，并把可配置状态传递给 Agent 草稿。

## 分开保存资源状态与授权状态

资源启用表示配置本身允许使用，租户授权表示当前租户是否允许继续使用。这两个判断各有含义，接口分别返回，页面也同时显示。

为了筛选和汇总，系统再给每项资源确定一个主状态：优先显示已撤销授权，其次是资源停用，再判断 MCP 是否准备好，剩余项显示为可配置。主状态互斥，分类数字可以与列表逐项对应；原始状态仍保留，避免把停用与撤销混为同一件事。

MCP 的准备条件使用已经保存的检测时间和工具目录。检测过却没有工具时，也不能把连接当成已有可选能力。这里没有在打开概况时主动联网，因此“可配置”只能说明当前记录满足条件，不能代替外部服务连通验证。

## 让概况独立于列表分页

原授权列表按资源类型分别读取，再为每个资源查询授权。资源数量增长后，这种方式既有读取上限，也增加数据库往返。

本次将四类资源投影为共同字段，通过 UNION ALL 与租户授权表关联。查询只包含名称、编码和状态等公开元数据，不需要读取模型密钥、连接正文或 Skill 指令。

列表在服务端搜索、筛选和分页，概况单独聚合完整目录。用户翻到第二页或只看一种状态时，分类卡片仍然表示整个当前租户。分页顺序包含资源类型、创建时间和编码，保持跨页读取稳定。

## 把授权范围落实到草稿选择

只在管理页显示撤销状态还不够。如果 Agent 编辑页仍允许选择该资源，用户要到发布时才会发现配置无效。

工作台现在分批加载授权目录。新选择会排除不可配置项，工具分组全选也采用相同条件。已有草稿中的撤销绑定继续显示，并允许取消，避免资源一旦不可用，反而无法从草稿移除。

模型选择保留原配置的展示，同时标记不可用，用户可以换成其他可用模型。这些界面约束帮助提前发现问题；服务端发布检查与 Runtime 的资源检查继续负责最终授权，不能由前端替代。

## 概况也需要遵守读取权限

拥有资源读取权限的成员可以查看目录，但不能修改租户授权。授权按钮与写接口要求租户管理权限，停用租户保留只读访问。

页面还会按权限显示成员与 Agent 数量。没有对应权限时，接口不返回该项统计，避免用一个汇总卡片绕过原有目录权限。原型中的额度或费用没有真实实现，本次也没有填入演示数字。

## 用跨页数据和实际授权操作验收

后端相关回归 16 项通过，覆盖 66 个混合资源、MCP 空工具、授权与停用交叉、角色和租户隔离。前端功能 48 项、UI 规则 6 项及类型检查、生产构建通过。

浏览器实际进入第二页并撤销工具授权，再到 Agent 草稿移除原绑定、选择同组可用工具，确认已发布版本没有变化。三种状态各检查六种视口，共保留 18 组记录。全部业务写入位于隔离库，没有调用付费模型或外部 MCP。

这一步让资源管理与 Agent 配置使用了相同的可用条件。下一阶段继续完善 SubAgent 关系的调用方式、超时与启停设置，并说明它们何时进入发布快照。
