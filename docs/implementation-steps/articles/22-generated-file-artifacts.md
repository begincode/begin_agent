# 模型说“文件生成了”，系统如何证明它真的交付了

模型返回一段报告文字，不等于用户已经拿到可下载文件。第二十二步给了模型一个明确的导出工具，但把发布权留在任务执行器。

工具必须被授权进 Agent 版本，最多生成三个有界文本文件。模型调用后得到的是“待任务成功提交”的回执；文件先留在本次执行内存中，任务中途失败不会留下看似完成的交付文件。

任务成功时先写私有对象，再在数据库同一事务提交文件元数据与成功状态。写对象失败就清理本次对象；数据库回执丢失则先核对，不能因为网络错误就删除已经关联成功任务的文件。对象存储和数据库之间仍可能因强制终止留下孤儿，因此还需要下一阶段的引用核对。

页面显示来源 Run、生成轮次、文件大小与哈希，用户下载经过原有任务权限校验。已知模型凭据在编码前脱敏，避免 Base64 绕开文本脱敏。

五项新增后端测试覆盖正常交付和关键失败边界，完整后端 261 项、前端 132 项及 UI 6 项通过。浏览器生成报告并核对下载哈希，12 组视口检查通过。系统用可追溯的文件记录完成交付，而不只相信一段成功描述。

浏览器发现生成文件下方仍写人工上传，已修正并隐藏空上传人，新增来源文案回归测试；重新完整构建、启动及六视口复验通过。
