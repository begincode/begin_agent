# 有备份文件，还需要证明系统能恢复

一次数据库导出只能证明某个命令执行过。真正恢复系统，还要找回文件对象和解密模型凭据的主密钥，并确认恢复后的账号、任务与下载路径仍然工作。

第二十四步将这三部分放进私有备份目录，用逐表摘要和逐文件哈希核对。备份目录不得覆盖，恢复目标也必须是全新的本机隔离库。真实演练暴露 public schema 已存在的问题，修复后仍保留“拒绝覆盖已有库”的约束。

演练恢复了 28 张表，模型凭据可以离线解密。浏览器登录恢复服务，看到了原任务，并下载到与恢复前相同的生成文件。这比只列出备份目录更接近实际可用性，但没有宣称生产回切或远程灾备完成。

同时增加对象引用核对。工具指出缺失、损坏和未引用文件，却不直接删除，因为数据库回执不明时留下的对象可能仍需调查。测试中特意放入一个孤立文件，报告找到了它，文件仍在、删除数为零。

完整后端 273 项、前端 133 项及 UI 6 项通过，恢复页面六视口验收通过。备份不仅要能生成，也需要一条经过执行的恢复路径。
