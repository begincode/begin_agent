# 把“本机能跑”变成可检查的部署条件

第二十五步先把部署要求变成可执行检查：Python、数据库版本、迁移、角色、持久目录和主密钥。检查失败要保留具体条件，不能为了显示绿色而跳过。

本机已有 Python 3.12 与 PostgreSQL 16，因此增加了一套独立实例和正式角色配置。完整后端在这套组合与原 3.14/17 环境各通过 279 项。实际预检发现 Worker 缺少迁移表读取权限；补齐最小授权后，让正式 Worker 启动也核对迁移，避免无效进程持续尝试领取任务。

离线包用目标 Python 构建，再装进全新的虚拟环境，从打包的启动模板运行 API 和 Worker。构建清单记录系统和架构，因为 macOS 的 wheelhouse 不能直接充当 Linux 包。当前主机的 Linux 严格检查仍然失败，这个结果明确保留。

浏览器登录正式角色启动的本地服务，34 页巡检通过。前端 135 项和 UI 6 项检查通过；200 次、20 并发的本机只读请求全部成功，p95 为 57.54ms。它说明这次有限读取验证通过，没有证明生产模型吞吐。

PMS 模板、授权脚本、只读预检与验证方法已交付，远程发布还需要真实平台登记、Linux、TLS和外部服务配置。把这些条件和证据区分清楚，交付才有可重复执行的下一步。
