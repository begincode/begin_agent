# 从本机进程号到共享心跳：让运行告警有明确含义

同一台机器上的 API 可以检查 Worker 的进程号，拆到其他主机后，这个判断就失效了。第二十三步把共同的观察点放到数据库：Worker 定期用数据库时间上报，API 只返回有效窗口内的数量。

数据库心跳与本机就绪检查各自保留。前者回答哪些实例仍在上报，后者能检查本机进程是否存在。两者都不能保证模型供应商或外部工具可用，因此页面直接解释采样范围。

告警从已有队列诊断生成，用户可以确认已查看。确认记录按账号和租户保存，不能替其他人消除提示，也不会把有故障的任务改成成功。样本变化以后重新提示，避免一次确认永久遮住后续故障。

本地数据库备份后升级到 20261106_08，既有 25 张表数据不变。真实独立 Worker 经历启动、退出和恢复；浏览器验证告警出现、确认持久化和恢复消失。后端 265 项、前端 133 项及 UI 6 项通过，12 组视口检查通过。本轮没有向外发送任何通知，后续接通知渠道可以建立在已有权限和样本定义上。
