# Begin Agent 建设实践之十一 平台用户目录与独立详情的设计与实现

平台用户管理已经具备账号创建、停用和密码重置，但列表一次只读取最多一百条数据，搜索在浏览器里进行。随着账号增加，旧账号可能从页面上“消失”，即使输入完整用户名，也无法在已加载的数据里找到它。

第十一阶段把目录查询交给服务端，并补上独立创建和用户详情页，让账号管理具备稳定入口和明确的权限边界。

## 搜索必须覆盖整个账号目录

新的目录接口按账号、显示名称、编码和历史标识查询，支持状态与平台管理员身份组合筛选，再按创建时间和不可变编码稳定排序。

分页默认五十条，最大一百条，使用 offset 继续读取。前端只展示服务端返回的当前页，不再过滤已经截断的列表。百分号、下划线按普通字符搜索，避免名称中的字符意外变成匹配规则。

验证专门准备了超过一百条账号，检查分页无重复，并确认最后创建之外的目标仍可通过账号名直接找到。这比验证十条演示数据更能说明目录能力是否完整。

## 账号资料与租户权限分别管理

平台账号负责用户名、显示名称、登录状态和平台身份；租户成员负责加入哪个工作空间、使用什么角色。用户详情只修改账号资料，不顺带改变租户成员记录。

详情使用不可变用户编码，可直接访问和刷新。历史开发身份没有内置用户名，页面明确只读，避免让人误以为它可以设置密码后登录。

目录和详情接口都要求平台管理员身份。隐藏菜单只是帮助用户理解权限，直接调用接口仍会返回 403。响应中也不包含密码哈希或数据库内部 ID。

## 保留账号操作的连带效果

停用账号会阻止登录并撤销会话；密码重置同样撤销该账号原有设备的登录。当前登录账号不能停用，最后一位平台管理员不能降权，这些保护继续由服务端执行。

修改本人资料后，页面重新读取身份，顶栏同步更新。本人降权后离开平台管理页；本人重置密码则需要重新登录，避免界面继续展示旧权限。

账号管理属于平台能力，即使当前租户停用，平台管理员仍然可以管理账号。这样也为恢复组织访问保留了必要入口。

## 在重新启动的页面上走完操作

相关后端十项、前端功能六十三项和 UI 规则六项通过后，重新编译并启动 API、Worker 与隔离验收实例。浏览器实际完成创建账号、修改长名称、刷新详情、重置密码后登录，以及普通账号越权检查和停用筛选。

三种页面状态覆盖六种规定视口，共保留十八组截图与几何数据；长英文名称不会撑宽手机内容区，控件继续遵循 40px 高、8px 圆角规范。

全部账号写入都在隔离库，实际服务只核对运行与登录页，保留用户原有账号和模型配置。接口、检查结果与证据见[第十一步交付文档](../11-platform-users.md)。

后续收尾又补查了平台管理员在非成员租户自行降权的情况：页面现在会回退到本人有权访问的租户并清除旧数据。该场景经过单测与浏览器验证，本步十八组视口也在最终构建上复验；最终完整检查见第十二步交付记录。
