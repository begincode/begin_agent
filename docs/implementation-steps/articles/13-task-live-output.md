# Begin Agent 建设实践之十三 任务实时输出与断线恢复的设计与实现

任务开始执行后，用户需要知道两件事：系统现在正在做什么，以及已经生成了哪些内容。此前任务页可以轮询状态和完整结果，但模型还在生成时，页面只能显示等待。

第十三阶段把已有模型流式能力接进任务执行链，让正文、思考过程和当前阶段在执行期间出现，同时处理刷新、断网和失败后的内容归属。

## 实时输出跨过了两个进程

模型请求由 Worker 执行，任务页面连接的却是 HTTP API。把片段放在 API 内存里广播，既无法让独立 Worker 直接发布，也不能在进程重启后恢复。

本阶段复用运行记录的可更新输出字段保存累积预览。Worker 合并片段后写入数据库，API 通过 SSE 发送最新快照。没有增加 Redis，也没有改写不可变的步骤和消息记录。

预览写入仍需持有有效租约。任务取消、租约过期或被其他 Worker 领取后，旧 Worker 不能再覆盖内容。这让实时展示沿用已有的执行所有权规则。

## 快照替换，避免重连重复

如果浏览器把每次收到的文字都直接追加，重连时重放的片段容易重复，新尝试的内容也可能混入旧输出。

这里发送的是带轮次、运行标识和模型调用序号的累积快照。浏览器用最新内容替换预览，相同版本忽略。刷新或重连后直接读取数据库状态，不依赖浏览器记住上次收到了第几个片段。

模型正文和思考各保留有限长度，片段按短时间间隔合并写入。上游暂时没有新片段时，已经接收到的内容也会落库。它提供持续更新的预览，但不声称一个 SSE 帧就对应一个供应商 Token。

## 预览和结果必须有不同含义

看到一段文字，不代表任务成功。网络可能在下一秒中断，工具可能失败，用户也可能取消执行。

页面因此把未完成内容标为实时草稿，失败或取消后改为“中断草稿 · 非最终结果”。只有完整模型协议和整个任务执行都成功后，正式 Task 输出才进入下一轮上下文并生成产物。

流连接结束也不直接当作成功。页面重新读取持久化结果，再根据任务状态决定显示正式正文还是中断草稿。

多轮检查还发现，单独保存最新快照会让旧失败轮次的草稿从任务页消失。本阶段补上各轮最近根 Run 的预览读取，刷新或继续对话后仍能回看中断内容，同时不把它加入成功上下文。

## 思考、阶段与访问权限一起更新

思考内容放进可折叠区域，模型、工具和子 Agent 的当前阶段单独显示。已完成的步骤继续使用原有记录，避免把尚未结束的工作伪装成成功步骤。

任务正文预览需要任务读取权限，子运行阶段还需要运行读取权限。持续连接会定期重新检查会话和角色，撤权后停止推送；轮询降级的任务详情接口也遵守相同边界。

凭据脱敏不能只处理单个片段。密钥可能被拆成几段输出，因此未完成的凭据前缀会暂时保留，等后续片段到达后统一脱敏，预览截断时也不释放这些前缀。

## 断网可以恢复，取消才停止任务

关闭页面只释放读取连接，不改变 Worker 的执行。断网时显示恢复状态，暂用轮询更新；网络恢复后重新读取最新快照，避免丢掉已经持久化的内容。

取消则通过任务控制接口执行。租约检查阻止后续写入，正在等待的上游读取被关闭，已经保存的草稿仍可查看。后台任务自身仍受预算和整体超时约束。

## 在重启后的真实链路上验证

自动检查最终通过后端一百八十五项、前端功能七十六项和 UI 规则六项。随后重新编译启动 API、Worker 和隔离验收实例，用合成流式模型驱动真实队列、Runtime、数据库与 SSE。

浏览器确认：正式结果仍为空时已出现正文和思考；刷新前后草稿一致；断网恢复没有重复文字。第一轮成功后产生一个产物，第二轮不完整流失败、第三轮取消均没有增加成功产物，刷新后两轮中断草稿仍然存在。

三种状态覆盖六种规定视口，共保留十八组截图和几何数据，另外补拍取消与历史草稿；三十四个页面巡检没有脚本异常。本轮没有调用真实供应商，没有数据库迁移，实际服务保留原有账号和模型数据。

接口、约束与证据见[第十三步交付文档](../13-task-live-output.md)。
