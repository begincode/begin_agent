# Begin Agent 建设实践之六 任务重新执行与文本产物的设计与实现

任务完成之后，用户的工作通常还没有结束。同一份要求可能需要再运行一次，生成的结果需要复制进文档，或下载后交给其他人使用。这些操作需要与任务历史、版本和权限保持一致。

Begin Agent 第六阶段补齐了成功任务重新执行、快捷键发送和文本产物复制下载。重新执行新增轮次，原结果继续保留；文本产物提供来源与版本，并直接交付原始内容。

## 重新执行需要明确来源轮次

任务持续对话时，最近要求会随轮次变化。用户页面可能已经过时，因此仅提交任务编码，还不足以表达希望重跑哪一轮。

新接口要求携带来源轮次编码。服务端锁定任务后，检查它是否仍为最新轮次，再用该轮的要求创建下一轮；状态已经变化时，明确要求刷新。任务继续使用创建时固定的 Agent 版本，后来发布的新配置不会影响这次重新执行。

已有成功轮次和结果保持原样，并继续作为任务上下文。这里的重新执行表达“沿着当前任务再处理一次最近要求”，需要全新上下文时应建立新任务。这个区别会影响模型实际收到的历史，也影响用户如何比较两次结果。

## 用幂等与权限处理重复操作

网络中断后，用户很难判断请求是否已被服务端接收。前端为一次重新执行生成幂等键，请求失败后继续保留它；服务端在任务锁内检查，同一键重复提交返回同一轮。

并发测试同时提交两次相同请求，确认只创建一个新轮次。不同请求在执行中提交会被拒绝，避免一项任务同时推进多个当前轮次。

拥有者仍需具备任务创建权限，任务管理者可以管理他人的任务，只读账号和其他普通成员不能借此发起执行。Agent 停用、租户不可写、超过轮次上限等约束也继续生效。固定测试任务保留专门的用例入口，避免普通重新执行改变测试语义。

## 快捷键与发送按钮采用相同条件

输入框支持 Ctrl 或 Command 加 Enter 发送，普通 Enter 保留换行。快捷键调用与按钮相同的发送函数，忙碌、只读、无权限和执行中状态都不能绕过。

组合输入也需要单独处理。中文等输入过程中，即使出现 Enter 键事件，也应先完成输入法操作；当前实现检查组合状态，防止误发尚未确认的文字。

## 交付原文并保留来源

文本产物展示生成时间、产物版本和来源 Run。产物版本对应生成轮次，用于区分同一任务的多次结果；Agent 的配置版本仍由任务与运行记录追溯。

复制使用产物原文，只有剪贴板写入成功才显示成功。浏览器不允许复制时，页面给出失败提示，并保留重试和下载入口。

Markdown 下载同样直接使用原始文本，保持标题、代码缩进和换行。文件名过滤路径分隔符与控制字符，避免产物名称改变下载路径含义；临时 Blob URL 在使用后或组件离开时释放。当前能力限定为文本产物，没有扩展到 PDF 或二进制文件存储。

## 用完整执行与文件比对验收

浏览器从真实表单创建任务，经队列与 Runtime 配合模拟模型生成第一轮结果，再通过重新执行按钮提交第二轮。验证确认原成功结果保留，固定版本没有变化。

第二轮生成后，实际读取剪贴板并保存下载文件，两者都与服务端原文一致，内容为 1674 UTF-8 字节。随后实际输入两行文字，用 Ctrl+Enter 发起第三轮，确认换行完整进入要求；验收完成后取消待执行轮次。

本轮最终完整后端 156 项、前端功能 44 项和 UI 规则 6 项通过。第六阶段三种页面状态分别完成六种视口检查，共保留 18 组记录。模型响应使用隔离模拟实现，验证的是任务复用、历史保留和文本交付链路。

具体接口、权限条件和下载证据见[第六步交付文档](../06-task-results.md)。
