# 第十五步 真实模型与 MCP 联调

日期：2026-11-06。状态：已完成当前约定范围。用户确认先完成“真实模型＋本机独立 MCP 服务”，外部业务服务后补。规格见 [需求](../specs/feature-live-model-mcp.md)，验收映射见 [验证报告](../specs/feature-live-model-mcp-verification.md)。

## 实现与使用

本步补齐真实执行链验收、运行诊断和 MCP 检测状态一致性，不增加新的任务执行引擎。

- 模型步骤保存供应商、型号、配置编码和经过格式及已知凭据检查的供应商请求 ID；失败只记录安全错误分类、HTTP 状态和重试属性。原始供应商错误正文与凭据不进入运行记录。已有历史步骤保持不变。
- MCP 工具步骤及实时阶段显示“服务名 · 工具名”，内置工具显示配置名称；步骤输入保留授权别名和源编码，便于从执行链追溯到连接。MCP 失败在工具步骤保存安全诊断码，不把失败工具输出当成成功结果或产物。
- MCP 协议层统一区分鉴权、限流、超时、网络、服务不可用、工具失败及协议/目录错误。发现当前 SDK 会将非 2xx HTTP 转成通用 JSON-RPC 错误，已在 HTTP 客户端边界保留最新 POST 数字状态和安全网络分类；不解析错误字符串来猜原因，不留远程正文或响应头。取消仍继续向上传播。
- 连接检测失败后保存 last_error、撤销 checked_at，旧目录仅供参考；新版本发布拒绝失败连接。页面在检测失败后刷新当前详情和资源目录，重载仍能看到明确错误；恢复成功清除错误。并发更改地址/凭据后，旧检测请求不能覆盖新配置。修改连接地址或凭据也会清除旧诊断。
- 界面明确“工具发现通过”不代表模型实际调用，工具执行以任务与运行记录为准。没有新增数据库表或迁移。

主要代码：`app/runtime/agent.py`、`app/tools/mcp.py`、`app/tools/errors.py`、`app/api/workspace.py`、`app/services/platform.py`、`ResourceEditor.vue` 和 `integrationStatus.ts`。

## 可复用验收工具

`python -m scripts.mcp_acceptance_server --token-file <0600文件> --port 18033` 启动只监听 127.0.0.1 的独立 MCP Streamable HTTP 服务。唯一工具 acceptance_add 完成受限整数加法并返回随机服务端 receipt，无业务写操作。可选事件文件仅记录测试结果与回执；可选控制文件支持本机故障注入，不开放管理 HTTP 接口。

`python -m scripts.verify_runtime_integrations` 使用外部会话令牌文件与当前租户，只读观察指定既有任务的 SSE、运行和产物，不创建任务、不触发模型。参数包括 `--base-url`、`--token-file`、`--tenant-code`、可重复的 `--task-code`、`--output`。报告检查真实模型步骤、请求 ID、子运行、MCP 步骤、动态回执及成功文本产物；单凭模型声称调用工具不能通过。真实供应商属性仍须由运行环境和供应商请求记录核对，脚本本身不会把任意测试网关认证为真实模型。

## 本轮真实结果

源配置只读，在专用 `begin_agent_step15_20261106` 数据库中重新加密模型凭据，创建独立账号、MCP 连接、两个父 Agent 和两个预处理子 Agent。API、Worker、MCP 为三个独立进程。真实供应商只接收固定验收文本与算术测试数据，不接收业务资料、源代码或 MCP 凭据。

先各做一次小请求检查连通性，再各运行一个完整任务。预处理子 Agent 串行返回 CHILD_READY；父 Agent 通过授权 MCP 工具计算 184+207，从工具获得不能预知的 receipt，随后返回包含结果、回执和子运行标记的正式文本。验收任务自动重试为 0，根模型最多 3 步，每次最多输出 2048 Token、整体预算 24000、超时 150 秒。

| 模型 | 完整任务 | 模型请求 | 供应商上报 Token | MCP 调用 | 结果 |
|---|---|---:|---:|---:|---|
| DeepSeek deepseek-flash | 子 Agent → MCP → 最终回复 | 3 | 1363 | 1 | 通过 |
| GLM glm-5.3-flash（Coding Plan） | 子 Agent → MCP → 最终回复 | 3 | 918 | 1 | 通过 |

完整任务共 6 次模型请求、2281 Token；加上两次连通性检查，本轮共 **8 次真实请求、2348 个供应商上报 Token**。用量不是费用账单。六次任务请求 ID 均保存，两个服务端 receipt 与不可变工具步骤及正式结果逐项一致。两任务都在终态前通过 SSE 读到预览，最终各产生两个成功 Run 和一份正式文本产物。

浏览器实际从任务表单提交 DeepSeek 任务；Worker 启动前在隔离库关闭该验收任务的自动重试。页面出现思考内容时，API 状态仍 RUNNING、正式 output 为空、产物为 0。完成后正文包含 MODEL_MCP_OK、391 和真实回执，执行链显示子 Agent 和 acceptance_add；刷新后结果仍一致。GLM 的完整执行也由真实 Worker 和只读 SSE 观察器验证。

MiniMax/Kimi 没有已保存可用配置，未执行真实调用；没有用假密钥、模拟数据或历史验证代替本轮结果。外部业务 MCP 按用户决定后补；本轮 MCP 是独立本机服务。
