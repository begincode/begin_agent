# 第九步 成员目录与权限详情

状态：已完成。对应成员列表和独立成员权限原型。

## 实现

- `GET /api/v1/members` 支持姓名/账号/角色搜索、成员状态与角色筛选、稳定分页；不再由浏览器过滤已加载数据。
- 新增 `GET /api/v1/members/roles`，有 `members.manage` 即可读取分配目录，不需要 `roles.manage`。停用或超出本人权限的角色标记不可授予，服务端保存仍校验委派边界。
- 新增 `GET /api/v1/members/{member_code}` 与独立详情路由，显示账号、成员、角色状态及实际权限，区分账号停用、成员停用和角色失效。内置平台管理员按真实身份优先级展示，不把成员停用误称为撤销平台身份。
- 页面只修改租户成员设置，不改全局账号姓名；保留最后管理员保护。未引入原型占位的“仅本人数据”范围，明确读取与任务操作沿用现有权限语义。
- 主要代码：`app/services/members.py`、`app/api/platform.py`、`MembersWorkspace.vue`、`AdminView.vue`、`PlatformApp.vue`。

- 前端完整 check：56 项功能测试、6 项 UI 规则测试、类型检查和生产构建通过；ruff 通过。
- 编译后实际 API/Worker 与隔离实例重新启动。浏览器实测仅有成员管理权限的账号分配自定义观察者角色、刷新详情、第二页和组合筛选；无角色编辑权限也能使用分配目录，不能选择租户管理员角色。
- 验证发现手机详情的长英文名称导致内部宽度从 315px 撑到 1067px。已修复标题换行，重新编译启动后复验，同时加入内部内容宽度检查。首次组合断言未通过后逐项核对保存结果与禁用选项，并补充明确状态等待再复验。

## 边界

角色分配与详情采用当前配置，角色后续变更需刷新查看。已有停用账号的成员设置仍需先恢复账号后再变更；账号恢复属于平台用户管理。没有新增数据库结构，未重置实际账号或密钥。
