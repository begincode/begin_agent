# 第六步 任务重新执行与文本产物

状态：已完成。补齐任务原型的重新执行入口、Ctrl/Command + Enter 发送及文本结果交付。

## 实现结果

- 新增 `POST /api/v1/tasks/{code}/rerun`，必传 `source_turn_code` 与 `idempotency_key`。成功的普通任务可重新提交最近一轮要求，新增轮次，沿用已有成功上下文和任务固定版本，保留原轮次输出。
- 任务锁内检查并发状态、来源是否为最新轮次、Agent 状态、100 轮上限及测试任务限制。同一幂等键重复提交返回同一轮；前端请求失败后保留原键重试。来源不是最新轮时要求刷新。
- 普通拥有者需要 `tasks.create`，任务管理者可通过 `tasks.manage` 管理他人任务；只读账号与其他普通成员无法重新执行。API 继续执行租户写入状态与归属检查。测试任务通过用例入口重新运行，失败/取消任务保留原重试入口。
- 新建任务和持续对话支持 Ctrl/Command + Enter；Enter 换行，组合输入和忙碌/只读/执行中状态不误提交。
- 新增文本产物组件，显示产物版本、时间与来源 Run。复制原文确认成功后才提示成功，失败可重试；下载原始 UTF-8 Markdown，文件名过滤路径与控制字符，Blob URL 在完成或组件离开时释放。非文本产物提示能力范围。
- 代码：`app/domain/workspace.py`、`app/services/conversations.py`、`app/api/workspace.py`、权限路由、`TaskWorkspace.vue`、`TaskArtifacts.vue`。

## 边界

重新执行会继续已有任务的成功上下文，并非清空上下文的独立评测。产物版本表示生成轮次，不等于 Agent 配置版本。当前提供文本复制与本地 Markdown 下载，不新增文件对象存储、PDF 或二进制产物能力。剪贴板仍取决于浏览器权限；失败时可下载。
