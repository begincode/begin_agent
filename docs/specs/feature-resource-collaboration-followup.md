# 租户资源与协作配置后续完善

用户已授权按设计继续第七步及后续功能，并要求每步完成验证与总结文章。本轮依据租户资源原型、Agent 协作原型和现有不可变版本机制，依次完成第七、八步。使用独立账号体系，不增加 SSO、计费或工作流引擎。

## 第七步 租户资源概况与授权

- 汇总当前租户四类资源总数、可配置、撤销授权、停用和待检测状态。资源启用与租户授权分别显示；MCP 还需已检测且有已发现工具。概况不受列表分页影响。
- 服务端搜索、资源类型/可用状态筛选、稳定分页；不依赖原有 1000 条上限或逐资源查询授权，不返回模型/MCP 密钥与连接正文。
- 有 `resources.read` 可查看，只有 `tenant.manage` 且租户可写时可修改授权；禁用租户保留只读访问。概况的成员与 Agent 计数服从相应读取权限，不展示虚构额度或费用。
- Agent 草稿区明确显示已撤销授权的资源：未绑定项不可新选，已绑定项可取消；工具分组全选排除不可用资源。后端发布与 Runtime 保持最终校验。
- PostgreSQL 验证分页、聚合、MCP 状态、授权/停用交叉、权限与租户隔离；前端完整 check；真实 Chromium 验证授权切换、筛选、草稿选择和六视口几何截图。

## 第八步 SubAgent 协作配置

- 已有关系支持调用方式、单次超时、启用状态编辑；新增关系拒绝重复、自调用、循环与跨租户。启用时检查完整有效关系图，停用关系可再次编辑/启用。
- 协作列表显示子 Agent 名称、状态及当前发布版本，读取不再仅返回启用关系；子 Agent 目录补齐分页，避免第一页之后的 Agent 无法选择。
- 关系修改只在重新发布主 Agent 后进入新快照；已发布版本和已创建任务保持原快照，不把关系停用误称为即时撤销历史工具权限。
- 验证并发图变更、重复关系、停用后反向边及重新启用的循环检查、固定子版本/模式/超时与权限隔离；前端测试与真实浏览器检查编辑、启停和六种视口。

## 交付

每步按实现、相关回归、前端完整 check、浏览器验收、交付文档与总结文章的顺序完成，再进入下一步。最后完整后端检查、页面冒烟、更新 18029 API/Worker 与本地 PMS 运行包。所有业务验证使用隔离数据库和模拟模型；不调用付费模型、不外部部署、不提交推送代码，不迁移无变化的数据库结构。
