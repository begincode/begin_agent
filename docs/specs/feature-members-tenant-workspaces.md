# 成员权限与当前租户工作区

用户授权继续第九步及后续功能，并要求每一步重新编译启动、浏览器验证、发现问题修复复验、整理文章。本轮按成员和租户设置原型，依次完成第九、十步。

## 第九步 成员目录与权限详情

- 成员列表服务端搜索、角色/成员状态筛选和稳定分页，展示成员、账号与角色状态，避免混淆访问受阻原因。
- 独立 `#/members/{member_code}` 详情，可刷新直达，显示当前角色、实际权限、加入时间及租户读取/任务操作范围；不伪造“仅本人数据”隔离。
- `members.manage` 可读取角色分配目录，无需取得角色定义编辑权限。目录标记可授予角色、停用角色和超出本人权限的角色；不能借此提权。
- 保存继续复用已有成员接口和最后管理员保护，不更改全局账号资料。成员停用、角色停用和平台账号停用均明确区分；平台管理员访问优先级按实际鉴权展示。
- PostgreSQL 验证分页、跨租户、委派边界和最后管理员；前端完整检查，独立浏览器实测角色分配、详情刷新、过滤与六种视口。

## 第十步 当前租户设置

- 当前租户信息独立读取/改名接口，目标由会话租户决定，不接收任意目标编码；有 `tenant.manage` 可改当前正常租户名称。
- 页面集中管理当前租户，展示不可变编码、创建时间、状态及按权限提供的真实概况。租户管理员不可越权切换全局状态；平台管理员保留创建租户和启停能力。
- 停用后保留历史只读，普通管理者不能写入；平台管理员可通过既有平台接口恢复租户。改名后顶栏目录同步更新，其他租户保持不变。
- PostgreSQL 验证当前租户隔离、权限、只读和平台状态边界；浏览器改名/刷新、权限和启停恢复，覆盖六种规定视口。

## 每步交付顺序

实现与自动检查通过后重新编译，更新实际 18029 API/Worker，启动隔离验收实例进行浏览器验证；发现问题则修改、重编译、更新服务并复验。通过后写交付文档与总结文章，再进入下一步。全量后端检查与最终页面冒烟在本轮收尾执行。

不新增数据库结构、不重置实际账号、不修改实际模型配置，不恢复 SSO，不调用付费模型，不提交、推送或合并代码。隔离数据库承载所有业务写入；实际服务仅做就绪、构建与登录页检查。
