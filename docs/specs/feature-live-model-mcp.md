# 第十五步：真实模型与 MCP 联调

日期：2026-11-06。用户授权实现、重新编译启动、浏览器验证与总结文章。

## 范围

- 使用既有 DeepSeek / GLM 配置运行真实网关、数据库队列、主/子 Agent、MCP 工具、SSE、运行记录与产物。真实请求仅发送固定验收文本，不发送业务数据、凭据或源码。
- 原始配置只读；在独立验收库创建账号、加密重新封装的模型配置和 Agent。保留原账号、主密钥及业务数据。MiniMax/Kimi 没有可用配置时明确未验证。
- 当前无外部 MCP 配置，用户确认先完成真实模型＋本机独立 MCP 服务，外部服务后补。提供独立运行的本机 MCP 服务，通过官方 SDK 连接并验证 Bearer 鉴权、工具发现、授权工具调用和动态回执。此服务不冒充外部业务 MCP。
- 增加可复用的 MCP 验收服务与任务联调检查脚本。检查脚本只读取已有任务/运行/SSE，不触发额外模型请求；区分连接检测、任务成功和工具/子 Agent 实际调用，并输出不含密钥的证据。
- 模型调用步骤保存供应商、模型、配置编码、请求 ID 与安全错误分类；不保存供应商原始错误正文。MCP 工具步骤显示服务和工具名称，并保留源编码及授权别名以追溯。
- MCP 协议错误统一归类：鉴权、限流、超时、网络、协议/参数目录和工具失败。检测失败保存安全错误码、撤销旧成功标记，页面刷新后仍明确未通过；配置变更时不得用旧请求覆盖新配置。重新成功检测清除错误。
- 不改变任务至少一次执行语义，不自动重放已输出模型流；外部写工具的幂等仍由下游保证。不恢复 SSO，不发布远程 PMS。

## 验收标准

1. 后端回归覆盖模型请求 ID 与错误分类脱敏、MCP 鉴权/工具失败/取消、检测失败状态落库和并发配置变更、已授权工具的真实协议调用。
2. 真实 DeepSeek 与 GLM 各至少一条完整任务成功，包含成功子 Run、真实 MCP 调用回执、正式产物，保留请求 ID 和用量。禁用队列自动重试，限制任务步骤/Token/超时；失败只记录真实原因并修复，不无限重复调用。
3. 浏览器展示实际真实任务实时输出、最终内容、工具与子运行，刷新后保留；工具回执来自 MCP 返回，不能只凭模型文字宣称工具执行过。
4. 浏览器验证 MCP 检测成功→错误→刷新仍失败→恢复成功，不回显凭据。所有副作用只限独立验收服务与隔离库。
5. 全量后端、前端 check、类型构建、Ruff；重新启动实际 API/Worker，保留实际数据。六视口截图/几何与页面巡检；问题修复后重跑受影响检查。
6. 独立实现文档、验证报告和总结文章分别记录真实供应商、本机 MCP、模拟错误与待接入外部服务，不混淆证据范围。
