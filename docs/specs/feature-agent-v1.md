# Agent 平台第一版

> 2026-10-29 范围变更：用户取消 SSO，当前身份方案以 [内置账号规格](feature-internal-accounts.md) 与 [本次验收记录](verification-prototype-accounts-20261029.md) 为准。原型补齐以 [补齐规格](feature-prototype-alignment.md) 为准。

用户已要求按现有技术选型及 ER 设计直接实现，接入 begin-sso 和 begin-pms。

## 范围与验收

1. Begin SSO：服务端登录重定向、state/PKCE、handoff 单次兑换、HttpOnly 会话、实时校验及当前/全部退出；401、403、503 区分；Cookie 写请求校验同源。
2. 多租户：SSO 主账号映射为平台用户；平台管理员创建租户、管理成员；每个实体查询和关联都验证租户；租户停用后保留历史只读访问、禁止新任务及模型调用；外部只使用实体编码；已有模型配置迁入本地租户。
3. Agent：配置、不可变版本发布、工具绑定及子 Agent 关系（拒绝循环），任务固定已发布版本和依赖快照。
4. 执行：PostgreSQL SKIP LOCKED、短事务领取、租约心跳、过期重领、有限重试、幂等、取消；执行结果必须由持有有效租约的 Worker 提交。
5. Runtime：有界模型/工具循环，子 Agent 串并行和按需调用、超时、深度/调用数/Token 限制，保存 Run/Step/Message 和最终文本产物。
6. 前端：保留聊天与模型管理，增加登录、租户切换、成员、Agent/版本/关系/工具、任务及运行链路页面。
7. PMS：按本机 begin-pms 的应用接入规范提供唯一构建产物、Python 版本声明、外部 YAML 配置、PMS 日志/持久目录、前缀与健康检查；HTTP API 与非 HTTP Worker 独立登记。用户已通过在线接入规范明确 PMS 为部署接入，不增加项目/需求联动。
8. 验证：后端单元及真实 PostgreSQL 集成测试；前端完整 check；真实浏览器六种规定视口、尺寸与截图；外部 SSO/PMS 无配置或不可达时明确记录，不能用 mock 冒充线上联调。

## 设计约束

不引入 Redis、独立消息队列、工作流或计费系统。已存在文件均未提交，保留原内容，仅在 codex/agent-v1 分支修改，不提交、不推送、不合并 master。工具第一版提供本地白名单实现，拒绝任意网络及 shell 执行。文件对象存储待获得实际接口后接入，文本产物直接保存 JSONB。

## 测试映射

身份：登录 state/PKCE、异常协议、失效/禁权、CSRF 与跨租户。配置：版本不可变/依赖快照/循环/权限。队列：并发领取/重领 fencing/取消/幂等/重试耗尽。执行：模型工具循环、子调用、预算与超时、失败脱敏。部署：配置优先级、PMS 目录检查、端口和前缀、迁移及打包。
