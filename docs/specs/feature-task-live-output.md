# 第十三步 任务实时输出

用户要求实现任务实时输出，每步重新编译启动、浏览器验收、修复复验并写总结文章。沿用内置账号，不恢复 SSO。

## 设计与边界

Worker 使用现有模型网关的流式接口，保存受有效租约保护的累积预览，再由 API 的 SSE 读取推送。API 与 Worker 为独立进程，不使用进程内广播、不增加 Redis 或队列组件。

复用可更新的 `AgentRun.output.live` 保存当前模型调用预览、思考内容及执行阶段，不新增表或迁移。`RunStep`、`RunMessage` 仍只保存既有完整记录，不修改不可变历史；正式任务/轮次输出只在完整模型协议及任务执行成功后提交。成功和失败的 Run 保留已持久化预览，标记为草稿，不加入成功上下文或产物。

每个模型调用的正文/思考预览分别限制 64Ki 字符，并显示截断提示；完整成功结果继续使用原限制。按短时间/片段合并写入与推送，不承诺供应商 Token 与 SSE 帧一一对应。默认模型网关使用流式；旧的仅实现 generate 的注入网关保留兼容，不在流中错误后自动重放请求。

## 验收标准

1. 任务执行期间逐片显示真实上游流的正文、可折叠思考及模型/工具/子 Agent 当前阶段；已完成步骤保持原记录。无 runs.read 时不泄漏子运行阶段或详情。
2. SSE 使用当前租户头与会话，流开始校验 tasks.read/任务归属，持续连接定期重新鉴权；账号/会话/角色失效停止推送。读取不触发任务或模型执行，断开页面不取消后台任务。
3. 预览写入每次校验有效租约、任务状态和取消标记，过期/被抢占 Worker 不可覆盖。客户端累计快照替换而非追加，刷新或重连不会重复文字；新轮次/尝试/模型调用明确隔离。
4. 流结束不等同成功。断流、错误、取消、超时保留已持久化草稿并明确未完成，最终结果从任务持久化接口核对；失败草稿不进入后续上下文或文本产物。
5. 连接建立、断线重连及轮询降级有明确状态，离开任务释放读取与定时器；恢复后继续读取最新快照。支持应用前缀、UTF-8 分片及 SSE 帧分片。
6. 累积预览脱敏，包括密钥跨片段输出；不返回原始系统提示、模型凭据或工具参数。完成态与部分输出分开渲染，Markdown 使用既有安全组件。
7. 自动测试覆盖真实隔离 PostgreSQL 的中途可见、租约 fencing、失败/取消/重试及权限；前端覆盖帧解析、断线恢复、终态/草稿和组件卸载。全量回归及前端完整 check 后重启实际 API/Worker 与隔离实例。
8. 独立 Chromium 使用隔离合成流式模型驱动真实队列/Runtime/SSE，验证完成前出现输出、刷新重连、不完整失败、取消和多轮；规定六种视口保留截图/几何数据，发现问题重编译复验。

所有业务写入只在隔离库。实际 18029 仅做就绪、最新构建、匿名登录页与 Worker 检查；保留原账号、模型配置和主密钥。不调用付费模型、不远程部署、不提交推送或合并。
