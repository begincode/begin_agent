# 修复角色操作权限不一致

## 复现与证据

2026-10-29，用户授权改用独立 Chromium。使用原编译产物、隔离数据库和独立账号在 18030 验收，实际原端口 18029 的账号数据不变。

1. 角色含 `agents.read/agents.publish/resources.read`、不含 `agents.manage`。配置页禁用输入，但展示“发布新版本”；点击后前端先 PATCH Agent、PUT 草稿，被拒绝，最终没有调用发布接口。
2. 角色含 `tasks.read/tasks.manage/agents.read`、不含 `tasks.create`。任务页展示“取消执行”；点击后中间件错误要求 `tasks.create`，返回 403。重试同受影响。
3. 自己创建的任务在角色改为只读后，任务页仍展示取消或重试按钮，点击才失败。

浏览器修复前证据：`output/playwright/rebuild-20261029/permissions-before.json`、`before-publisher.png`、`before-task-controller.png`。

4. 手机截图中长账号名在居中按钮内从两端裁切，自定义角色直接显示 `rol_...` 机器编码。改为省略号显示账号名，并返回/展示当前用户的角色名称。

## 预期与修复范围

- 发布者可直接发布已保存的草稿；不要求也不替其写入 Agent 或草稿。配置编辑者保持“先保存再发布”行为，不修改不可变版本与版本回滚规则。
- 任务取消、重试支持 `tasks.create` 或 `tasks.manage`，仍由业务层验证任务创建者/管理者与租户范围。`tasks.manage` 不自动授予新建任务和追加消息的权限。
- 只读角色不展示取消/重试按钮，服务端仍拒绝越权请求。
- 不改角色目录、默认角色或数据库结构，不触碰原库中的管理员初始化、模型配置。
