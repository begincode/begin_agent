# 第十七步：系统运行状态与运维诊断

日期：2026-11-06。依据原型补齐规格中的系统状态页、独立 API/Worker 部署设计，以及第十六步后的现有实现。仓库此前未定义第十七步编号，用户已确认本轮按系统状态与运维诊断范围实施。

## 范围

- 沿用 `/integrations` 页面和 `/api/v1/integration-status`，要求 `tenant.manage`。展示采样时间、数据库迁移、当前主机可观察的 Worker 心跳、登录模式和 PMS 托管状态。
- 队列指标额外要求 `tasks.read`，只统计当前租户：待执行、可领取、延后、运行中、过期租约、等待超过五分钟及最近一天失败/超时。列出最多十条异常任务及详情入口，不返回提示词、正文、凭据或 Worker 标识。
- 读取诊断不领取、重试或修改任务。停用租户可只读查看。数据库诊断失败返回脱敏的未知状态，不伪造正常；身份验证本身不可用时仍沿用认证接口错误。
- Worker 仅报告本机共享数据目录内可验证的状态，不把本机 PID 检查当作跨主机存活检测；损坏、过期、其他主机与扫描截断有明确说明。
- 页面有初始加载、刷新、失败重试与陈旧标记；离开/切换租户中止请求，旧结果不能覆盖新身份；不自动高频轮询。

## 验收

1. 后端测试覆盖队列时间边界、租户隔离、权限、停用租户、脱敏错误；Worker 覆盖新鲜/过期/损坏/异地主机记录。
2. 前端测试覆盖加载、真实零值、无任务权限、错误后重试、刷新旧样本、请求取消与旧响应丢弃。
3. 完整后端/Ruff、前端 check 通过；重新编译重启实际 API/Worker，独立隔离库通过浏览器验证正常、异常、恢复和权限场景。
4. 六种规定视口截图和几何检查通过；完成交付记录、验证报告和独立总结文章。

不增加数据库结构、Redis、Prometheus、远程部署、外部告警通知或自动恢复动作。保留既有账号、密钥与不可变历史，性能和故障验收使用隔离数据，不调用模型供应商。
