# 平台用户与角色权限工作区

用户授权继续完善，承接前十步，依次完成第十一、十二步。沿用独立账号体系，不恢复 SSO，不改变真实账号、模型、密钥和历史执行数据。

## 第十一步 平台用户管理

- 平台管理员可在 `#/users` 按账号、姓名、编码搜索，按账号状态、平台身份筛选，服务端稳定分页；兼容既有数组响应，默认 50 条、最大 100 条，支持 offset。
- `#/users/{user_code}` 独立详情可刷新直达，显示账号、编码、名称、状态、平台身份和创建时间；历史开发身份明确只读，不伪造可登录账号。
- 独立创建页；编辑姓名、状态、平台身份及重置密码复用原接口。保留最后平台管理员、当前账号不可停用、停用和重置撤销会话等保护；不回显哈希或密码。
- 修改本人信息同步顶栏身份；本人降权离开平台管理页，本人重置密码后重新登录。租户只读不妨碍平台账号管理，普通用户无权访问平台目录与详情。
- 后端验证超过 100 条目录、组合筛选、字面量搜索、详情越权和会话撤销。前端完整 check，重新编译启动后独立 Chromium 验证创建、搜索分页、编辑刷新、密码重置和停用；六种规定视口。

## 第十二步 角色权限页

- 保留角色创建、编辑、停用及不可超出本人权限的保护；内置角色只读。
- 角色目录新增服务端搜索、状态筛选、稳定分页，内置角色与自定义角色统一分页；保留原 `roles`、`permissions` 响应键。
- 有成员管理权限时展示各角色当前租户成员总数和启用账号/成员数量，明确这不代表可登录人数；禁用角色、平台身份和租户只读仍影响实际访问。
- 按权限目录展示矩阵，支持只查看或编辑所选角色；编辑影响当前使用此角色的成员，历史 Agent 版本和任务不修改。
- 受限角色管理者不能将超出自身权限的角色覆写为低权限，界面只读且服务端拒绝，避免间接撤销不属于其管理范围的权限。修改自身权限后重新获取身份并更新导航；不能停用当前使用的角色，避免失去当前租户访问入口。
- PostgreSQL 验证分页、成员统计、跨租户、停用/委派与自身权限变化。前端完整检查，重新编译启动后浏览器验证矩阵、编辑、成员实际权限联动和六种视口。

## 交付与范围

不增加数据库结构。每步实现 → 自动检查与编译 → 重启实际 API/Worker 和隔离验收实例 → 浏览器验证/修复/复验 → 交付文档和总结文章，再进入下一步。

所有业务写入仅在隔离库。实际 18029 仅检查就绪、构建与匿名登录页；不发起真实供应商调用、不远程部署、不提交推送或合并。最终完整后端回归、页面巡检、本地 PMS 运行包逐文件同步并记录证据。
