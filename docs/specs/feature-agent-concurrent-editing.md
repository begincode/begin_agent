# 第十八步：Agent 多人编辑并发保护

日期：2026-11-06。用户已确认范围：避免 Agent 草稿和协作配置被其他编辑者覆盖，增加冲突提示与重新加载。承接第八步的多人覆盖限制，复用现有草稿修订号，不引入数据库结构变更。

## 实现范围和验收

- Agent 元数据、草稿保存及可选发布在一次事务内完成。任一验证失败不得留下元数据、草稿或新版本的部分写入。
- 提供一致读取的配置快照和强 ETag。保存、发布、回滚、关系增改删使用 If-Match 条件请求：缺少返回 428，过期返回 412，不自动重试覆盖。旧草稿接口继续使用既有 revision 比较；元数据独立更新也使用条件检查。
- 配置快照包含元数据、草稿及协作状态；发布条件同时涵盖当前子 Agent 版本。图事务锁与 Agent 行锁采用一致顺序，保留循环检查、租户/RBAC、停用只读和不可变历史。
- 页面收到冲突保留本地表单，阻止重复保存，提供重新加载；明确确认放弃本地编辑后才替换。重新加载失败保留本地内容。离开页面取消读取，旧响应不得覆盖其他页面。
- 两个独立浏览器会话验证元数据/草稿、协作编辑/删除、发布冲突和恢复；确认数据库没有部分覆盖，历史任务仍绑定原版本。所有业务写入位于隔离库，无供应商调用。
- 完整后端/Ruff、前端 check，重新编译启动 API/Worker，六种规定视口的截图/几何及页面巡检通过，整理实施文档、验证报告和独立文章。

ETag 对比可见配置内容，不是租户鉴权凭证或全系统修订号；不锁定模型供应商、外部资源服务或跨系统编辑。接口调用方需先读取 ETag 后写入，不提供强制覆盖或自动合并。
