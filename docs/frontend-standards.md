# 前端开发规范

适用范围：`web/` 下所有前端代码、样式、依赖和构建配置，以及对前端行为有影响的静态资源修改。前端有变更就必须校验。

## 控件尺寸与外观

| 项目 | 规范 |
|---|---|
| 按钮、单行输入框、下拉框、思考折叠标题 | 统一高度 40px，使用 `var(--control-height)` |
| 控件圆角 | 统一 8px，使用 `var(--control-radius)` |
| 普通输入边框 | 1px，复用 `--control-border` |
| 背景、文字、焦点 | 复用 `--control-background`、`--control-text`、`--control-focus`；同类状态保持一致 |
| 内边距 | 单行控件上下为 0，内容垂直居中；桌面通常左右 10～14px，窄屏可适当缩减 |
| 同排布局 | 高度与底边一致，实测偏差不超过 0.5 CSS px；文本和图标不能偏上、偏下或挤出边界 |
| Logo、图标 | 在自身容器内水平和垂直居中，中心偏差不超过 0.5 CSS px；不要靠空格或随意位移补偿 |
| 禁用与焦点 | 禁用可识别、不可触发；键盘焦点可见；所有表单控件使用一致焦点边框与提示 |

共享变量集中在 `web/src/style.css` 的 `:root`。模型选择、思考模式、思考级别、配置表单、顶部操作和发送按钮都属于同一控件体系。新控件必须复用，不得单独再出现 34px、38px、7px 等近似规格。媒体查询也不得覆盖统一尺寸。

明确的例外：多行消息输入框可更高，但边框、圆角、焦点样式一致；复选框采用 16px 方形尺寸，不强制做成 40px；工具栏折叠行可以是整行操作。主要操作、次要操作和深色代码区可使用不同语义配色，不能因此改变高度与圆角。新增尺寸档位须作为明确设计变更一起更新规范与检查。

## 内容格式与交互

- 每条回复的模型名、参数摘要、思考信息、正文、用量和错误提示放在同一个完整卡片中。
- assistant 正文渲染 Markdown；标题、列表、表格、引用和代码块结构正常。模型原始 HTML 不执行，危险链接和脚本不能进入可执行 DOM。
- 代码块有语言标识、高亮与一键复制；复制原文保留缩进和换行。只有实际复制成功才显示成功反馈，失败可重试。
- 流式、不完整代码围栏、停止、失败和输出截断均有明确状态；不得丢失已返回内容，不得将失败输出当作完整成功历史。
- 页面不能把“配置已保存”显示成“接口已验证”。

## 响应式与边界

必须覆盖：320×800、390×844、768×1024、1280×720、844×390、390×360（CSS px）。最后一项是低高度检查，不能冒充真实手机软键盘实测。

- 页面无横向溢出：`document.documentElement.scrollWidth <= innerWidth + 1`；外层页面不产生多余纵向滚动。
- 输入区在可见视口内，聊天区自身滚动。模型配置表单可自身滚动，不把输入区挤出屏幕。
- 窄屏模型选择和操作按钮不互相遮挡；思考参数可展开、收起；输入框和下拉框字体避免触发移动浏览器自动放大。
- 表格和长代码在卡片内部横向滚动，不能撑宽整页。测试长模型名、长文本、宽表格和长代码。
- 不禁用用户缩放；保留底部安全区域；改变视口或键盘可见高度时检查布局。

## 每次改动的校验流程

在项目根目录执行：

```bash
npm --prefix web run check
# 等价入口
make web-check
```

该入口依次完成：现有前端功能测试、UI 规则检查器的正反例测试、源码控件规则检查、Vue/TypeScript 类型检查及生产构建。`npm run build` 也先执行 UI 规则检查；`make web-build` 使用完整检查入口。

UI 规则检查器扫描 `src/**/*.css`、Vue 组件样式，并收集 Vue 模板的控件类名，拦截单行控件私设高度、圆角、局部统一变量覆盖和模板内联尺寸。它不计算浏览器布局，也不保证颜色、实际对齐、遮挡、未知动态类或运行时生成样式全部正确。禁止把静态检查通过当作 UI 已全部验收。

界面、布局、样式、交互变化必须追加真实浏览器检查：

1. 打开本次构建的页面，检查空会话、正常回复、相关表单及本次受影响的状态。
2. 通过元素边界尺寸检查控件高度、底边、Logo/图标中心；不能只凭肉眼或源码推断。
3. 影响布局或响应式时完成上述六种视口，记录页面宽高、聊天区和输入区边界。
4. 检查宽表格、长代码、焦点、禁用、加载及本次修改涉及的交互，并保存可复查截图。
5. 交付说明列出自动检查与浏览器检查的结果；未执行或无法验证的项目明确说明。

CI 工作流 `.github/workflows/frontend-checks.yml` 在前端、规范、Makefile 或工作流变更的 Push/PR 中运行自动检查。工作流文件需要提交并推送至启用了 GitHub Actions 的仓库才会触发；真实浏览器视觉验收目前仍为必做的独立步骤，未宣称已自动化。
